The project chat ​

The Chat drawer (Ctrl+Shift+K) shows the messages of one Slack channel: the channel the selected row's folder maps to. The records the window holds are listed oldest first, and the newest sits at the bottom. The view follows the newest, so a message that arrives takes the bottom line and lifts the rest. An empty channel shows no messages.

To read older messages, scroll up: PageUp and PageDown move a third of the drawer, Alt+Up, Alt+Down and the mouse wheel one line. A reader scrolled up stays where they are: a message that arrives, is edited or is deleted does not move the view, and a message deleted at the reader's place stays there as (message deleted); the next one takes the place only when a new snapshot or the trim drops it. End (chat.latest) returns to the newest and follows it again, and scrolling down to the newest does the same. Two cases move the view: once the drawer holds its 100 newest messages, each arrival drops the oldest, so a reader on the oldest message moves up one message per arrival (until older pages can be read); and deleting or shortening the newest message can bring the newest wholly into view, which returns the reader to following. Switching to another row's channel starts at its newest.

Each message starts with its own header line: the author's name, a tag for a post that came from the drawer, a row or a bot, and the time (HH:MM for today, with the date for an earlier day). The text follows as typed.

Which channel ​

The hub's chat.toml maps a folder to a channel; a row whose folder is mapped shows that channel. How the mapping is written is in the chat configuration. The drawer follows the selected row. Markup shows as markup ​

A message is shown as its poster typed it. Slack's markup, such as a mention or a link, is shown as the markup text in its own color and is not rendered: a link is not clickable and a mention is not replaced by a name. Text that looks like a header inside a message stays body text.

Deleted messages ​

A message deleted while the drawer watches stays in its place, with its author, time and origin, and reads (message deleted). It counts toward the 100 messages the drawer keeps. A new snapshot (the window reads one after any loss of the chat feed) drops it, since the snapshot holds only what Slack still has.

When Slack is unreachable ​

The title does not show the state of the Slack connection. A socket outage shows only when it costs a snapshot, as not up to date. The drawer keeps the records it holds until a new snapshot replaces them. no messages appears only for a channel that was read whole and holds none.

Not yet ​

Posting from the drawer, older pages of history, threads and sharing a selection with the agent are not built yet. Each arrives with its own change, and this page says so when it does.
