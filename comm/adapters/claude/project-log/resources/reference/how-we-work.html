How we work

This page is the single statement of how the record and the repository are kept. Everything else in the record follows it.

In short The record has three tiers that change at three speeds: a frozen charter, a living status page, and an append-only journal. The unit of the record is the experiment page, written as a small scientific method. Every page starts in plain words and gets more detailed as you read down. Code lives in modules with tests or in thin runner scripts, and scratch work lives in one disposable folder.

Three tiers, three speeds

TierHoldsChanges
Charter (charter/)The goals, the questions, the concepts, the theory, the definitions of what is measured.Frozen. A change is a dated amendment block at the top of the page, never an in-place edit. Each page carries the date and commit at which it was frozen.
Status (status.html)Where each campaign stands, what is next, what blocks.Rewritten in place whenever the state changes. Describes the present only; never recites history.
Journal (journal/)Dated entries: what was done, decided, found, or abandoned.Append only. An entry is never edited after the day it is written; a correction is a new entry that links back.

Experiment pages and reference pages sit outside the tiers: an experiment page is updated until its status is complete or superseded, and reference pages are living lookups.

The experiment page

Every experiment gets one page, started from templates/experiment.html, with the sections below in this order. There are two kinds, marked by a kind badge on the status line and listed in separate navigation sections: a computational experiment runs code on simulated or recorded data and its Methods name the inputs, the seeds, the command, and the code at a commit; a wet-lab experiment runs on physical samples and its Methods name the sample, the preparation and measurement protocol, and the analysis pipeline. The scientific form is the same for both.

  1. Status badge: planned, running, complete, qualified, or superseded.
  2. In short: three to five sentences, no symbols, no numbers. The question, the answer so far, and what it does and does not license.
  3. Hypothesis: what we expect and what would show it wrong. For a quantitative test, the null and the pass margin, fixed before the run.
  4. Methods: what is held fixed and what is under test, the inputs, the seeds, the command, and links to the protocol and the code at a commit.
  5. Results: tables and figures. Every number traces to an output row.
  6. Conclusions: the verdict, what it means for the program, and the next step it implies.
  7. Provenance: commit, environment hash, seeds, output paths, date, and who ran it.

Pages are grouped by campaign under experiments/. A campaign overview is a table of its experiment pages with their badges.

Plain-language rules

The reader knows the field and does not know this project.

  • Assumed: the field's standard vocabulary. The glossary lists these terms in one line each, for completeness only.
  • Introduced in plain words on first use per page, then named, then linked to the glossary: every term this project coined and every method the field does not use daily.
  • Every page opens with an In short block. No symbol appears above the first heading.
  • Theory pages keep their derivations and carry one plain sentence before each equation block saying what the equation states.
  • Numbers go in tables, not sentences. One idea per paragraph. A reader can stop at any heading with a true picture.
  • Use the project's own words for the same thing everywhere; do not introduce a synonym for a defined term.

What happens when

  • A result lands. The runner writes its output with a provenance row. A journal entry records what ran and links the row and the commit. The experiment page is written or updated. The campaign overview and the status page are updated in place.
  • The plan changes. A journal entry says what changed and why. The status page is rewritten. The charter is untouched unless a question or a definition itself changed; then a dated amendment.
  • Something is abandoned. A journal entry, nothing else, unless a reader would otherwise repeat it, in which case one line on the status page.
  • A review lands. Findings that change the approach or a result go into a charter amendment, the status page, or the experiment page. Everything else is one line in the journal. Normative documents carry no caveat lists.

Where code lives

PlaceRule
src/, test/The reusable package. Code enters when a second experiment needs it or the charter cites it. Docstrings, tests, an API overview.
experiments/<campaign>/One folder per campaign with its own environment. PROTOCOL.md is the normative specification the code implements and lives next to it. src/ is a module holding all logic. scripts/ are thin runners that parse arguments, call the module, and print a sentinel. test/ holds the checks. output/<experiment>/<seed>/ holds logs and result rows, which are committed; caches are not.
project-log/figures/Figures the record cites. A figure from an experiment run is copied here from output/; a figure that exists only to illustrate a page is generated straight here. The record is self-contained.
dev/Scratch: plans, notes, spikes. Disposable, and never cited by the record. Work is promoted from here to an experiment module and then to the package.
data/A link to shared storage. Nothing under it is tracked.

Provenance is computed before any output file is opened, so a dirty flag means the code was dirty. Dependencies are added with the language's package manager and the environment files are committed.

The record itself

  • Hand-written HTML with no build step. Scripts generate figures only.
  • The navigation list and the site name live at the top of assets/site.js and are edited by hand when a page is added. A section with no pages is not shown.
  • Clicking a link to a record page swaps only the content column in place; the sidebar is rendered once per load and never moves.
  • Math renders from a vendored copy of KaTeX under assets/katex/, so pages render offline and when hosted.
  • New experiment pages start from templates/experiment.html; new journal entries start from templates/journal-entry.html, are named YYYY-MM-DD-slug.html, and get one line in the journal index.
  • assets/VERSION records the template version; refreshing assets/ and templates/ never touches page content.
