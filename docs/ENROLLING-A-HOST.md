# Enrolling a host for cross-frontend access

A box is **enrolled** when any frontend in the fleet can select its rows,
attach to one, and type — without that frontend having an account, a key,
or a route to the box. The route is: frontend → its own forwarded port →
the **hub**'s socket for that box → one `ssh` from the hub → `sotd
stdio-bridge` on the box → that box's daemon. The hub is the only machine
that ever ssh's in; ADR 0048 is the decision, this page is the procedure.

Everything here is run by an operator, once per box. Nothing in it is
automatic, and every step has a check that fails loudly — "it looked
right" is not one of them.

## What the hub ends up holding

`sotd topology apply --yes`, run on the hub, writes and enables **one
listener per enrolled host**:

| File (in `~/.config/systemd/user/`) | What it is |
|---|---|
| `sot-host-relay-<host>.socket` | the listener, at the path `sotd topology relay-sockets` prints; `Accept=yes`, `SocketMode=0600` |
| `sot-host-relay-<host>@.service` | one instance per accepted connection: `ssh … <host> sotd stdio-bridge --label sot`, the connection as its stdin/stdout |
| `sot-host-relay-<host>.socket.d/topology.conf` | `ConditionHost=<hub>` — the fleet shares `$HOME`, so the unit must run on the hub only |

Both unit files are **generated by `apply` and rewritten on every run**.
A hand edit to them is lost; a per-host override belongs in a drop-in
beside them (any name but `topology.conf`, which is apply's own):

```ini
# ~/.config/systemd/user/sot-host-relay-<host>@.service.d/local.conf
[Service]
Environment=SOT_RELAY_SOTD=/home/<user>/.local/share/sot/bin/sotd   # not on the ssh PATH
Environment=SOT_RELAY_LABEL=sot                                     # a second daemon on the box
Environment=SOT_RELAY_TARGET=<ssh alias>                            # alias ≠ declared host name
```

The host sits in the unit's **name**, not after an `@`, because a
templated socket with `Accept=yes` hands its service the connection id and
not the socket's instance (systemd issue #19071) — a per-host prefix is
the only spelling in which the service knows which box to ssh to.

## The checklist

Each step's check must pass before the next one is worth doing.

1. **ssh, from the hub, non-interactively.**
   `ssh -o BatchMode=yes <host> sotd --version` prints a version.
   A prompt, a host-key question or a "command not found" here is the
   whole enrolment failing early: nothing downstream runs attended. If
   `sotd` is found interactively but not this way, note its full path for
   the `SOT_RELAY_SOTD` override above rather than editing shell profiles.

2. **`sotd` runs as a user service on the box**, started by the OS, not by
   a launcher, surviving with nobody logged in. On the box:
   `systemctl --user is-enabled sotd.service` (plus `loginctl enable-linger`
   where that applies) and `sotd status` answers. An instrument box wants
   this regardless of anything on this page.

3. **The bridge answers.** From the hub, pipe one hello frame through
   `ssh -o BatchMode=yes <host> sotd stdio-bridge --label sot` and get the
   daemon's own reply, byte for byte, with nothing else on stdout. Record
   the label the box was enrolled with. With the daemon stopped, the same
   command must exit nonzero **at once**, one line on stderr, nothing on
   stdout — an honest failure, not a hang.

4. **Multiplexing is on.** The generated service already passes
   `-o ControlMaster=auto -o ControlPath=<runtime>/sot-host-relay-ssh-%C
   -o ControlPersist=600`, so no ssh-config change is needed for this
   alone. Prefer the config file when the host needs its own user, port,
   key or jump host anyway — put the multiplexing there too and keep one
   place to look:

   ```
   # ~/.ssh/config on the hub
   Host <host>
       ControlMaster auto
       ControlPath ~/.ssh/cm-%C
       ControlPersist 10m
   ```

   Check, after a frontend has connected: the hub's journal shows one ssh
   connection serving several bridge instances, not one connection each
   (`journalctl --user -u 'sot-host-relay-<host>@*'`).

5. **Update ownership is safe to move.** Declaring `daemon = true` makes
   the box's own backend the owner of its updates instead of its
   frontend's self-update. Confirm the box's backend is healthy and at the
   expected version *before* step 6, not after.

6. **Declare it, one box at a time.** In the hub's canonical
   `~/.config/sot/hosts.toml`:

   ```toml
   [host.<host>]
   daemon = true
   frontend = true   # only if it runs a frontend of its own
   ```

   Then on the hub: `sotd topology apply` (a dry run — read it) and
   `sotd topology apply --yes`. It must enable exactly one
   `sot-host-relay-<host>.socket` and disable nothing you did not expect.
   On every other box: `sotd topology sync`.

7. **Verify end to end.** On the hub, `sotd status` reports that box's
   real rows through `unix:<runtime>/sot-host-<host>.sock`. From another
   machine, relaunch the frontend: the host appears in Hosts mode, its
   rows in Sessions mode, attaching to one gives a read-write pty, and
   typing at the box itself takes the pen back.

## Reading a failure

- **The socket file exists and the box is down.** Expected, and not a
  contradiction: systemd owns that socket, so it is present whether or not
  anything is behind it. The frontend renders the host unreachable and
  greys its last-known rows. Only a completed hello ever means "up".
- **A frontend logs `has no relay socket on hub '<hub>'`.** The box is in
  the plan but the hub has no listener for it — step 6 was not applied on
  the hub, or apply ran while the box was not yet declared.
- **`sotd topology apply` refuses.** It only runs on the hub, and says so,
  naming the hub. Run it there.
- **The bridge instance fails per connection.** `journalctl --user -u
  'sot-host-relay-<host>@*'` has ssh's own line: a refused key, an unknown
  host key, or `sotd: command not found` (step 1's check, and the
  `SOT_RELAY_SOTD` override).
- **Every remote host went unreachable at once.** That is the hub, not a
  per-host fault: peers reach every enrolled box *through* it now.

## Removing a box

Delete its `[host.<host>]` block on the hub, `sotd topology apply --yes`
(which disables the listener and removes both generated unit files), and
`sotd topology sync` elsewhere. Nothing needs doing on the box itself —
the hub was the only side holding a route.
